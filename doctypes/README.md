# ประเภทเอกสาร (doctypes) — วิธีสอนระบบให้จัดรูปแบบเอกสารประเภทใหม่

ระบบเป็นแบบ **hub ตรงกลาง + ประเภทเอกสารเสียบเพิ่ม**:

```
app.py + web/index.html      hub: หน้าโปรแกรม, รายการไฟล์, ตัวเลือก PDF/ที่บันทึก, เปิดไฟล์ผลลัพธ์
core/                        ส่วนกลางที่ทุกประเภทใช้ร่วมกัน (อ่านไฟล์, ชิ้นส่วน Word HTML, แปลงด้วย Word, ไฟล์ข้อมูล)
doctypes/<รหัส>/              หนึ่งโฟลเดอร์ = หนึ่งประเภทเอกสาร (กฎ/รูปแบบ/ข้อมูลของเอกสารนั้นทั้งหมด)
   bt31/                     บฑ.31 หนังสือเชิญ/ขออนุมัติอาจารย์พิเศษ (ประเภทแรก — ใช้เป็นตัวอย่างแบบเต็ม)
   _template/                แม่แบบสำหรับประเภทใหม่ (ไม่แสดงในโปรแกรม เพราะขึ้นต้นด้วย _)
tools/learn.py               เครื่องมือวัดรูปแบบจากไฟล์ตัวอย่าง และเทียบผลลัพธ์กับตัวอย่าง
```

hub ค้นทุกโฟลเดอร์ใน `doctypes/` เอง (`core/registry.py`) — **เพิ่มประเภทใหม่ไม่ต้องแก้ hub เลย**
โฟลเดอร์ใหม่จะขึ้นเป็นการ์ดในแถว "ประเภทเอกสาร" ด้านบนของหน้าโปรแกรมทันที
ถ้าประเภทไหนโหลดไม่ได้ (โค้ดผิด) หน้าโปรแกรมจะแจ้งเตือน แต่ประเภทอื่นยังใช้ได้ตามปกติ

---

## สิ่งที่ต้องเตรียมก่อนสอนเอกสารประเภทใหม่

| สิ่งที่ต้องมี | ทำไม |
|---|---|
| **ไฟล์ดิบ** จากระบบ 3–5 ฉบับ (ครอบคลุมกรณีต่าง ๆ เช่น ไทย/อังกฤษ, ช่องว่าง, ข้อมูลยาว) | ใช้เขียนตัวอ่านไฟล์ และหากรณีที่ระบบสร้างข้อความผิด |
| **ฉบับที่เจ้าหน้าที่จัดแล้ว** ของไฟล์ดิบชุดเดียวกัน (.docx หรือ PDF) | เป็น "คำตอบ" — ทุกกฎต้องมาจากการเทียบคู่นี้ |
| ชื่อไฟล์ผลลัพธ์ที่เจ้าหน้าที่ใช้ | ตั้งชื่อไฟล์อัตโนมัติ |
| ข้อมูลที่ไม่มีในไฟล์ดิบแต่ต้องใส่ (ผู้ลงนาม ที่อยู่ เลขที่หนังสือ ฯลฯ) | เก็บใน `data/*.json` ให้เจ้าหน้าที่แก้เองได้ |

เก็บไฟล์ตัวอย่างไว้ที่ `doctypes/<รหัส>/samples/` — โฟลเดอร์นี้ **ไม่อยู่ใน git** (มีชื่อ/เบอร์โทรจริง และ repository เป็น Public)

## ขั้นตอน

### 1. วัดรูปแบบจากฉบับที่จัดแล้ว

```bash
python tools/learn.py inspect "doctypes/<รหัส>/samples/<ฉบับจัดแล้ว>.docx"
```

ได้ทุกบรรทัดพร้อม ฟอนต์ / ขนาด / ระยะจากขอบซ้าย / ระยะห่างจากบรรทัดก่อน และสรุปค่าที่พบบ่อย
(ฟอนต์หลัก, ระยะบรรทัด, ตำแหน่งย่อหน้า, ขอบกระดาษ) → นำไปตั้งค่าคงที่ในส่วน layout ของประเภทนั้น
(ดูตัวอย่างค่าที่ได้จริงใน `bt31/layout.py`: `FONT`, `LH`, `INDENT`, `DOC_TYPES`, `SIGN_CENTER`)

### 2. เทียบข้อความดิบกับฉบับจัดแล้ว

ไล่ดูว่าเจ้าหน้าที่ **ตัด / เปลี่ยน / เติม** อะไรบ้าง แล้วเขียนเป็นกฎทีละข้อ พร้อม comment ว่ามาจากตัวอย่างไหน เช่น
ยุบช่องว่างยาว, `09.00-12.00` → `09.00 - 12.00`, ตัด "อื่นๆ" ที่ระบบใส่แทนตำแหน่ง, ชื่อวิชาใช้ภาษาอังกฤษ
(ดูกฎทั้งหมดของบฑ.31 ใน `bt31/letter.py` และ `bt31/export.py` → `normalize()`)

### 3. สร้างโฟลเดอร์ประเภทใหม่

1. คัดลอก `doctypes/_template/` เป็น `doctypes/<รหัส>/` (รหัสเป็นภาษาอังกฤษ ไม่ขึ้นต้นด้วย `_`)
2. แก้ตามจุด `TODO` ใน `__init__.py`:
   - ข้อมูลประเภท: `id` (= ชื่อโฟลเดอร์), `name`, `description`, `icon`, `color`
   - หน้าจอ `ui`: ช่องวางไฟล์ (`slots`) และแท็บ (`modes`) ถ้ามีหลายทางเข้า — ดูความหมายทุกช่องใน `core/doctype.py`
   - `parse()` อ่านไฟล์ดิบ → `build_html()` จัดหน้าตามขั้น 1–2 → `output_stem()` ชื่อไฟล์
3. เอกสารที่ซับซ้อนให้แยกไฟล์แบบ `bt31/`:

   | ไฟล์ | หน้าที่ |
   |---|---|
   | `__init__.py` | คลาส DocType: ข้อมูลประเภท + หน้าจอ + ส่งต่อ inspect/convert |
   | `letter.py` (หรือชื่อแบบจำลองของเอกสารนั้น) | โครงสร้างข้อมูลเอกสาร + กฎข้อความ + ชื่อไฟล์ |
   | `layout.py` | รูปแบบหน้ากระดาษ (ค่าที่วัดได้จากขั้น 1) |
   | `<ทางเข้า>.py` | ตัวอ่านไฟล์แต่ละแบบ เช่น `export.py` (ไฟล์ .doc), `eform.py` (PDF) |
   | `data/` | ไฟล์ข้อมูลที่เจ้าหน้าที่แก้ได้ (ใช้ `core.store.JsonFile`) |

ชิ้นส่วนกลางที่ใช้ได้เลย:

| โมดูล | มีอะไร |
|---|---|
| `core.text` | `read_source` (อ่านไฟล์ export ทุก encoding), `to_lines`, `paragraphs`, `clean`, `safe_stem` |
| `core.wordhtml` | `paragraph`, `label_table` (ตาราง ป้าย : ค่า), `signature_block` (บล็อกลายมือชื่อวัดด้วยฟอนต์จริง), `font_css`, `wrap_document` (A4 ตาม `assets/word_head.html` หรือส่ง head ของตัวเอง) |
| `core.render` | `render(entries)` แปลง Word HTML → .docx/.pdf ด้วย Word ทีเดียวทั้งชุด, ฝังโลโก้, ชื่อซ้ำเขียนทับ (ไฟล์เปิดค้าง = ชื่อใหม่) |
| `core.store` | `JsonFile` อ่าน/เขียนไฟล์ข้อมูล JSON |

### 4. ตรวจผลกับตัวอย่าง

```bash
python app.py --serve        # เปิด URL ที่พิมพ์ออกมา → เลือกประเภท → ลากไฟล์ดิบมาวาง → ปรับเอกสาร
python tools/learn.py compare "<ผลลัพธ์>.pdf" "doctypes/<รหัส>/samples/<ฉบับจัดแล้ว>.docx" -o ผลเทียบ
```

อ่านผล 2 ส่วน:
- **บรรทัดข้อความ (ตัววัดหลัก):** "บรรทัดข้อความตรงกัน N/M · ตำแหน่งคลาดเคลื่อนสูงสุด …" ตามด้วยบรรทัดที่มีเฉพาะฝั่งใดฝั่งหนึ่ง
  เกณฑ์ผ่าน: แนวตั้งคลาดเคลื่อนไม่เกิน ~1 pt, แนวนอนไม่เกิน ~6 pt และบรรทัดที่ต่างต้องอธิบายได้ทุกบรรทัด
  (เช่น ตัดบรรทัดต่างกัน 1 คำ หรือไฟล์ตัวอย่างพิมพ์ผิด) — ถ้าตำแหน่งเพี้ยนหลายจุด ให้กลับไปขั้น 1–2
- **พิกเซล:** ดูภาพ `1-side.png` (ซ้าย = ของเรา, ขวา = ตัวอย่าง) และ `1-diff.png` (สีแดง = ต่าง) ด้วยตา — ตัวเลข % สูงได้มาก
  (30–70%) แม้หน้าตาเหมือนกัน เพราะการกระจายตัวอักษรแบบไทยต่างกันเล็กน้อย ใช้ตัวเลขนี้ได้ตรงเฉพาะเมื่อทั้งสองไฟล์
  ถูก Word สร้างจากต้นทางเดียวกัน (~1% = ระยะคำ)
ทำกับไฟล์ตัวอย่างทุกฉบับ (ไม่ใช่แค่ฉบับเดียว)

### 5. ออกรุ่นให้เครื่องอื่น (เมื่อเจ้าของตกลง)

```bash
python tools/release.py "เพิ่มประเภทเอกสาร <ชื่อเอกสาร>" -i "รายละเอียดที่เจ้าหน้าที่จะเห็น"
python tools/release.py --push        # เผยแพร่ — เฉพาะเมื่อเจ้าของสั่ง
```

คำสั่งแรกตรวจความพร้อม (ทดสอบผ่าน, โหลดทุกประเภทได้, ไม่มีไฟล์ตัวอย่าง/ไฟล์เฉพาะเครื่อง, ไม่มีชื่อบุคคลจริงในโค้ด) → เพิ่มเลขรุ่น
ใน `version.json` + เขียน `CHANGELOG.md` → commit → ติดป้าย `v<เลข>` → สร้างโฟลเดอร์ `dist/อัปเดต version <เลข>/` (ส่งต่อได้ทันที)
หลัง `--push` เครื่องอื่นจะเห็นแถบ **"มีอัปเดตใหม่"** กด **อัปเดตเลย** ครั้งเดียว — ติดตั้งเฉพาะรุ่นที่ออกแล้ว
(ข้อมูลที่เครื่องนั้นเรียนรู้/แก้เองใน `data/` ไม่ถูกเขียนทับ · รายละเอียด HANDOFF.md หัวข้อ 11)

### 6. บันทึกความรู้ไว้ให้คนต่อไป

- เขียนที่มาของกฎสำคัญใน docstring/comment (เทียบจากตัวอย่างไหน) — เมื่อรูปแบบเปลี่ยน จะได้รู้ว่าต้องวัดใหม่ตรงไหน
- เพิ่มประเภทใหม่ในตารางของ `HANDOFF.md` หัวข้อ 2
- commit เฉพาะโค้ดและ `data/` — **ห้าม commit `samples/`**

## ปรับรูปแบบของประเภทที่มีอยู่แล้ว

ขอฉบับที่เจ้าหน้าที่จัดแบบใหม่ → `learn.py inspect` ดูค่าที่เปลี่ยน → แก้ `layout.py` ของประเภทนั้น → `learn.py compare` จนตรง
